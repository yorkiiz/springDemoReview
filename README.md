## 开发顺序### 顺序说明

| 原因 | 说明 |
|---|---|
| **基础设施先行** | 统一响应和异常处理是所有接口的"地基"，后面每个接口都会用到 |
| **安全加固紧跟** | 注册接口依赖安全体系，角色动态化影响后续所有接口的权限控制 |
| **商品先于订单** | 创建订单需要调用库存扣减，商品模块是订单的前置依赖 |
| **订单先于支付** | 支付是对订单的后续操作，必须先有订单才能支付 |
| **前端最后** | 后端接口全部就绪后，前端再对接，避免反复修改 |# springDemoReview
